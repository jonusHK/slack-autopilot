# 설계 — 정책 파일 계약 (`AUTOMATION.md`)

- 상태: 초안 (2026-08-13)
- 대상 레포 루트의 `AUTOMATION.md` 가 그 프로젝트의 판단 기준 전부다(D-001). **이 파일이
  없으면 엔진은 그 레포의 어떤 항목도 구현하지 않는다**(전 불릿 ❓).
- 소비자는 LLM 에이전트다 — 형식은 산문 마크다운이되, **아래 섹션 제목은 고정**한다(엔진
  프롬프트가 섹션명으로 참조한다). 각 섹션의 내용은 프로젝트가 자유롭게 쓴다.

## 필수 섹션 6종

### 1. `## 채널`

이 레포를 구동하는 슬랙 채널을 **이름 + 환경변수 이름**으로 적는다(예: `#dev` /
`SLACK_CHANNEL_ID`). **원시 ID 를 파일에 쓰지 않는다** — 식별자도 환경변수로만 둔다.
엔진 설정이 참조하는 변수 이름과 이중 기재이므로, 어긋나면 처리하지 않는다(오배선 방어).

### 2. `## 티어 경계`

무엇이 Q(봇이 답변)·A(자동 구현)·B(사람 결정 대기)인가. 엔진의 범용 휴리스틱(engine.md §4 —
"무엇에 재량이 있으면 B, 물음표·검토·~어때는 무조건 B")** 위에** 얹는 프로젝트 규칙만 쓴다.
반드시 답해야 하는 질문:

- 이 프로젝트에서 **자동화가 절대 건드리면 안 되는 경로**는? (예: 안전 파이프라인, 결제)
- **사용자 노출 문구**의 신설·변경은 어느 쪽인가?
- **스키마·계약 변경**을 동반하는 작업은 어느 쪽인가? 동반 절차(슬라이스 등)가 있는가?
- **Q 의 범위**: 봇이 답해도 되는 질문의 경계. 이 프로젝트에서 봇이 **답하면 안 되는** 질문이
  있는가(예: 안전·법무 해석은 사람이 답한다)?
- 분류 오판이 발견되면 **이 섹션에 사례를 추가**한다 — 수선 지점은 엔진이 아니라 여기다.

### 3. `## 검증`

- CI 워크플로 이름 목록(전부 그린이어야 "그린").
- 필수 리뷰어 에이전트(어떤 변경에 어떤 리뷰어 — 예: 웹 화면 변경 시 design-reviewer).
- pre-commit 가드 목록과 **우회 환경변수 이름**(엔진의 우회 금지 목록으로 쓴다 — D-004).

### 4. `## 병합 금지선`

- 충돌 시 자동 해소하지 않고 ❓ 로 넘길 파일 목록.
- 재번호 규칙: 순번이 붙는 파일(마이그레이션·결정 로그 등)의 패턴과 재번호 방법. 없으면 "없음".

### 5. `## 결정 기록`

스레드 답글로 내려온 결정을 어느 문서에 어떤 형식으로 기록하는가(D-006 — 슬랙에만 남은
결정은 결정이 아니다). 예: "결정 로그 `docs/product/decisions.md` 에 새 PD 로, 색인 행과 함께".

### 6. `## 구현 규율`

- 구현 에이전트가 따라야 할 그 레포의 지침 위치(보통 CLAUDE.md — "이 파일을 읽고 따르라"
  한 줄이면 된다).
- **구현 위임 대상**(비용 통제): 그 레포 `.claude/agents/` 에 있는 **에이전트 이름**과,
  위임하면 안 되는 **예외 경로**. 미지정이면 세션이 직접 구현한다.
  - **모델 이름만 적지 않는다.** 세션은 자기 모델을 실행 중에 못 바꾸므로 "구현 모델: Sonnet
    고정" 같은 문장은 **실행할 수단이 없다.** 실제로 그렇게 적어둔 정책이 한 줄도 지켜지지
    않은 채 남아 있었다 — 엔진이 읽고 할 수 있는 일이 없었기 때문이다. 거는 대상은
    에이전트여야 한다.
  - 예외 경로는 **경로·주제로 구체적으로** 적는다. "중요한 곳"은 판정이 안 된다.
- 커밋 메시지 관례(트레일러 등).

## 작성 원칙

- **정책은 이 레포(엔진)가 아니라 대상 레포에 산다** — 그 레포의 규칙 문서·가드와 같은
  커밋에서 진화해야 하기 때문(D-001).
- 짧게 유지한다. 엔진 프롬프트가 매 실행 읽는 파일이다 — 근거·서사는 그 레포의 결정
  로그에 두고, 여기는 **판정 규칙만**.
- 짧을수록 좋다. 매 실행 읽히는 파일이다.
