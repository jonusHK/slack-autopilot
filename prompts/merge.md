# 루틴 프롬프트 — 병합 (5단계)

> 자동 병합은 없다(D-005). 사람이 PR 을 읽고 🚀 를 단 것만, **순차로** 병합한다.

## 1. 검출

```bash
cd ~/slack-autopilot
# .env 는 로컬 실행용 — VM 에는 없다(값은 환경변수). 있을 때만 읽는다.
[ -f .env ] && { set -a; . ./.env; set +a; } || true   # 없어도 실패가 아니다
python3 bin/detect.py --channel "$SLACK_CHANNEL_ID" --mode merge --days 14
```

`[]` 이면 **아무 보고도 남기지 말고 즉시 종료**한다.

노드는 🚀 가 붙고 ✅ 가 없는 메시지다. 보통 **PR 링크가 담긴 봇 답글**이다. 링크가 없으면
스레드를 읽어 찾는다. 끝내 못 찾으면 ❌ 와 함께 "어느 PR 인지 못 찾았어요"를 남긴다 —
추측해서 아무 PR 이나 병합하지 않는다.

## 2. 순차 처리 (동시 금지)

**한 번에 하나씩** 처리한다(원안의 싱글 스레드). 병렬로 병합하면 재번호와 충돌 해소가 서로를
덮는다. 여러 건이면 오래된 것부터.

각 PR 마다:

1. `python3 bin/github_api.py pr-get --repo "$TARGET_REPO" --pr <url>`
   (바뀐 파일 목록은 `pr-files`, 병합은 `pr-merge`)
   - `merged` 가 참이면 ✅ 만 붙이고 넘어간다(재실행 안전).
   - `state` 가 `closed` 인데 병합이 아니면 ❌ 와 사유.
2. **CI 확인** — `python3 bin/github_api.py checks --repo "$TARGET_REPO" --ref <head_sha>`.
   `success` 가 아니면 병합하지 않는다. ❌ + `failed` 의 검사 이름.
   `none`(붙은 검사 없음)은 통과가 아니다 — ❓ 로 사람에게 묻는다.
3. **금지선 확인**(정책 파일 `## 병합 금지선`). 아래에 걸리면 병합하지 말고 ❓ + 이유:
   - 정책이 나열한 금지선 파일이 충돌에 포함
   - 정책이 나열한 민감 경로가 diff 에 포함
   - 같은 함수 본문이 양쪽에서 바뀐 **로직 충돌**
4. **재번호**(정책 파일 `## 병합 금지선` 의 재번호 규칙). 순번이 붙는 파일(마이그레이션·결정
   로그 등)이 기본 브랜치와 겹치면 **병합 직전에** 다시 매긴다. 아직 기본 브랜치에 없는 새
   파일이라 안전하다. 규칙이 "없음"이면 이 단계를 건너뛴다.
5. 병합한다. 정책이 병합 방식을 지정하지 않았으면 그 레포의 관례를 따른다.
6. ✅ 를 붙이고 답글에 **무엇을 병합했는지 + 충돌을 어떻게 해소했는지** 남긴다. 충돌이
   없었으면 없었다고 적는다 — 다음 사람이 "조용히 뭘 했나" 궁금하지 않게.

## 3. 절대 규칙

- **🚀 없이는 병합하지 않는다.** CI 가 그린이어도, 사소해 보여도.
- **🚀 를 붙이지 않는다.** 사람 전용이다(`bin/mark.py` 가 막는다).
- 충돌을 "일단 이쪽 걸로" 해소하지 않는다. 규칙으로 풀리는 것(재번호)만 자동이고, 나머지는
  ❓ 로 사람에게 간다. 자동 병합의 사고는 조용해서, 발견될 때는 이미 기본 브랜치에 있다.
- 병합 후 브랜치 정리는 그 레포의 관례를 따른다. 애매하면 남긴다(지우는 것은 되돌릴 수 없다).
